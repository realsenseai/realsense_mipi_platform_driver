D585 2C Passive Depth 驱动测试

不依赖 SDK。2026-10-21 按 PR #702 对齐。离线测试提取并编译 d4xx_main.c 中实际 GET/SET 与整机 idle helper，不是另写的协议模型。 硬件 ioctl 程序只在显式指定设备路径时访问设备；make 不运行它。

冻结接口

D500_CAMERA_CID_PASSIVE_DEPTH = DS5_CAMERA_CID_BASE + 17 = 0x009A4011。 仅 D58x 深度节点注册，active 2C 时可见；3C 不可见。MENU 使用 VOLATILE 和 EXECUTE_ON_WRITE，确保同值 SET 也执行忙检查。

控件名为 2C Passive Depth Mode。

值菜单
0Disabled
1Alternating Passive
2Full Passive

实际 FW 模式寄存器为 0x4531（1 字节），替换 PR 中明确未定的 0x453a 占位值。 驱动不再依赖本地原有的 0x45F0 完成状态扩展，也不进行 sequence polling。

整个 GET/SET 在物理设备 mutex 下进行。SET 要求 Depth/RGB/IR/IMU 全部 idle， 包括 IMU-only。先 GET 探测：0xFF 返回 EOPNOTSUPP，其他越界值返回 EBADMSG； 随后写模式并 GET，读回不一致返回 EIO。GET 在 idle/streaming 均可用。 保持 PR 的值读回契约：空闲同值写被 FW 内部拒绝时，单看相同值不能证明该次事务执行； 整机 streaming busy 由驱动前置检查保证，同值 SET 也返回 EBUSY。

必须先确认固件版本、active 2C 与正确深度 video 节点。 整个设备流程需统一设备锁，固件部署、枚举、开流与清理都在同一锁内， 不得嵌套获取锁。以下只展示独立 idle 测试：

hkr_device_lock run -- ssh -T -o StrictHostKeyChecking=yes jetson@192.168.112.216 \
  '/path/to/deployed/passive_depth_ioctl --idle /dev/video-rs-depth-0'

上述路径需替换为 216 的实际部署路径。开发机没有 GMSL 环境， 硬件 ioctl/采流仅在 216 执行，110 用于串口；本地只运行离线测试。

idle 检查 QUERYCTRL/QUERYMENU、0/1/2 GET/SET、同值 SET、非法值。 任何写入前先快照现有两个可读写激光控件： 0x009A4001（emitter 开关）与 0x009A4002（manual laser power）； 缺失、不可读写或读取失败则拒绝模式写入。清理先恢复模式，再恢复功率， 最后恢复用户 emitter 开关，并逐项 GET 校验。单纯恢复原始模式不够， 因为同值 SET 也会重置 emitter/alternate/strobe 派生策略。 alternate/strobe 没有独立 V4L2 CID，由模式恢复其派生策略； 不宣称恢复通过其他 transport/HWMC 设置的隐藏状态。

模式 SET 遇到超时、I2C、EINTR、EIO 或其他不确定结果时，明确报告 UNKNOWN、保存的原始 mode/emitter/power，禁止任何后续写入和自动恢复。 即使一次 GET 看起来没改变，也不能证明异步请求不会稍后完成； 必须先对固件完成状态进行外部核对，不能盲目重发恢复模式。 idle 测试仅将框架 ERANGE 拒绝视为明确未提交； 其他 errno 不能区分固件拒绝与完成后读状态的 I2C 错误，保守报告未知。 busy 测试只接受预期 EBUSY 和未改变的 GET，本身永不执行恢复写入。 SIGINT/SIGTERM 在结果确定时触发退出和恢复尝试； 硬件断开、未知结果或外部 owner 抢占可能导致无法恢复，程序明确失败，不伪报恢复成功。

--busy /dev/videoN 用于同一持锁流程内已由测试方启动的 Depth、IR 或 RGB 流：确认 GET 可用，同值 SET 返回 EBUSY 且模式不变。 本工具不创建/停止任何流，不停止其他客户端。对每类流分别执行； IMU-only 同样应执行 busy 测试并返回 EBUSY。3C/旧固件、设备重启后的模式、 并发共享图 owner、图像和 metadata/激光证据仍需端到端硬件验证。 V4L2 MENU 非法范围由框架返回 ERANGE，而非固件 INVALID 的 EINVAL。
